# First 30 achievements: proposal for owner review

Owner preference: cosmetic medals, no new combat stats. This is a reviewed-data proposal, not an enabled award
service. Use existing medal art/names, grant zero-stat copies, and never modify the ordinary quest version of a
medal. Exact normal-client appearance and every hidden/equipment-set stat source still need verification before
claims can be enabled. New events must represent completed work, not accepted requests.

The medal names are existing client labels, not new custom titles. Some pairings are deliberately broad; the owner
can change them before implementation. No rewards, combat stats, mesos, EXP or items are granted by this proposal.
Do not backfill past boss/PQ/fishing/streak events that are not recorded. Existing level/job facts may seed only
those corresponding goals. Bots use the same verified event rules; fixed staff and roster bots need durable
progress independent of their current actor type.

## Implementation decisions still to settle

- Final goal/medal pairings and class-cap/fourth-job definitions.
- Daily streak reset boundary (propose Pacific calendar days; no double-counting repeated login that day).
- A single durable progress/claim design shared by real-player and bot saves, atomic with inventory writes.
  A claimed flag written separately from the item can lose or duplicate a reward after a crash. Do not copy that
  weakness or claim exactly-once behavior from an in-memory test. Include disconnect/restart/full-bag tests.
- Medal copies must not contribute equip stats, hidden WZ bonuses or set bonuses. Keep ordinary copies unchanged.
- A failed/unconfirmed claim needs an operator-visible receipt and a safe recovery route.
- Goal 30 stays unavailable until the dungeon actually exists. No imaginary completion event or daily-life goal.

Progress/award code and deployment remain pending. This proposal is the concrete owner-review checkpoint for ticket 93.
