**Why it matters.** `src/main/java/config/YamlConfig.java:19-29` (the reader is at `:22`) is a plain
`YamlReader` with no strictness: any key absent from `config.yaml` leaves that field at the JVM default. The
shipped template carried six keys — `CHARSET`, `DB_HOST`, `DB_USER`, `DB_PASS`, `DB_URL_FORMAT`,
`PARTY_SEARCH_REENTRY_LIMIT` — plus an empty `worlds:` list, so 13 boot-critical fields read 0. The measured
consequences:

- `ITEM_EXPIRE_CHECK = 0` makes `TimerManager.register` (`src/main/java/server/TimerManager.java:97-99`,
  `scheduleAtFixedRate` with a 0 period) throw `IllegalArgumentException` from the `expireItemsTask` registration
  inside `startItemMonitor()` at `MapleMap.java:990`, reached from `addPlayer` -> `MapleMap.java:2891`, swallowed
  at `PlayerLoggedinHandler.java:501`, aborting the rest of login;
- `MAP_VISITED_SIZE = 0` throws `IndexOutOfBoundsException` at `Character.java:2112`;
- `MOB_STATUS_AGGRO_INTERVAL = 0` throws `IllegalArgumentException` from the `TimerManager.register` call at
  `src/main/java/net/server/coordinator/world/MonsterAggroCoordinator.java:90-93` (the 0 period argument at
  `:93`), so `startAggroCoordinator` never returns; the division at `:98` would also divide by zero but is never
  reached.

**Proof already recorded** (`/root/work/agent-runs/server/164-configtemplate/REPORT.md`): fail-before
`Tests run: 4, Failures: 4`, including
`IllegalStateException: config.yaml has no 'worlds:' entries; at least one world is needed.`; pass-after
`Tests run: 4, Failures: 0`; the whole `config.*Test` set `14 / 0`.

**Merge hazard.** The lane was cut at `c589cf49d`. The integration tip has since taken `164-familycfg`
(`6cea00b4e`), which adds four `FAMILY_*` initialisers to the same `ServerConfig.java` region
(`ServerConfig.java:486-489`). The template already carries those four keys at the same values
(`config.example.yaml:422-425` on the lane: 4 / 20 / 200 / 1000), so this is at worst a small textual conflict in
that region, and the lane's file is the one to keep.

## Part E — the lane protocol

Every lane Claude spawns follows this, or it will corrupt shared state:

1. Own worktree, branched from the current integration tip (`git worktree add -b <lane> <path> 163-integration`).
2. `git config extensions.worktreeConfig true`; `git config --worktree remote.origin.pushurl DISABLED`.
3. Copy `/root/work/SlumsMS/config.yaml` into the worktree (gitignored; without it ~52
   `ExceptionInInitializerError` from `YamlConfig.java:22`).
4. No `git stash` (one stash list shared by every worktree), no push, no rebase, no merge of other lanes.
5. No full suite from a lane — the parent runs it once after all lanes land. Targeted `-Dtest=` runs only.
6. Trailers on every commit, verbatim:
   `Co-Authored-By: DeepSeek <noreply@deepseek.com>` and

7. `REPORT.md` at `/root/work/agent-runs/server/<lane>/REPORT.md`, with the fail-before and pass-after runs pasted
