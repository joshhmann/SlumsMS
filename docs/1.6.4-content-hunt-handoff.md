### The one contaminated run, and how it was disproved

The merge-9 full suite ended `Tests run: 9775, Failures: 8, Errors: 207` with 295 `NoClassDefFoundError`s
(`TempleLanes` x38, `DecideShadow` x23, `InitiativeScenarios` x15, `BotTickService` x8, `InPacket`, ...) and
`MockitoException: Mockito cannot mock this class: class client.Character.` caused by
`InternalError: class redefinition failed: invalid class`. Cause: another process rebuilt
`/root/work/SlumsMS-163-integration/target/` while surefire was running — all 3984 `target/classes` `.class` files carry
an mtime inside that window, and every class named in a `NoClassDefFoundError` loads under
`javap -cp target/classes` afterwards. The same window aborted the first `scripting.*Test` run after merge 5.

Recovery, not a retry-for-luck: the final suite was run after the tree was quiet, `find target -name '*.class' -newermt
"<suite start>"` is empty (main classes written once at 23:49, test classes 23:49/23:50 by that suite's own compile),
and it shows 0 `NoClassDefFoundError` and 0 failures. The authoritative result for merges 9-11 is therefore
`10479 / 0 / 0 / 146`, not the 9775 line. If you ever see `NoClassDefFoundError` in a suite run, check for a concurrent
build before you check for a regression.

## Environment traps

- **`config.yaml` is gitignored and tests need it.** Every new worktree needs `cp /root/work/SlumsMS/config.yaml
  config.yaml` before running any test that boots `YamlConfig`.
- **Per-worktree git config.** `git config extensions.worktreeConfig true` then
  `git config --worktree remote.origin.pushurl DISABLED` in the worktree you own. The pushurl is SHARED repo config if
  you set it without `--worktree`, and `git remote set-url --push` writes exactly that.
- **No `git stash`, ever.** All worktrees share one stash list.
- **WZ is not in the repo.** Tests that need it take `-Dwz-path=/root/slums-nav-v70/wz` (the nav port's copy);
  `soloMapling.WzTestData` gates on it, so a missing path turns into skips, and a WZ decision made in `@BeforeAll`
  turns into `Tests run: 0` (that was 164-testassume).
- **DB-backed monsterbook tests** exist on `163-integration` only (the lane that added them). The split is **4 + 2**:
  `client.MonsterBookTierRowTest` has 4 `@Test` (`:85`, `:101`, `:123`, `:138`), all gated by the one
  `Assumptions.assumeTrue(URL != null && !URL.isBlank(), "no scratch MySQL given (-Dslums.monsterbook.it.url)")` inside
  `@BeforeEach void reset()` at `:45`; `client.MonsterBookTierPersistenceTest` has 2 `@Test` (`:96`, `:109`), each gated
  inline at `:98` and `:111`. So a no-DB suite skips 4 + 2 = 6, and none of them is ungated. Do not read those skips as
  coverage, and do not look for the files on `release-1.6.4` before the lanes merge.
- **One known flake:** `soloMapling.Environment.PlatformGroundTest.aBandAcrossTwoLevelsPutsEachSpawnOnItsOwnLevel` uses
  the unseeded `private static final Random random = new Random();` at
  `src/main/java/soloMapling/Environment/PlatformSpawner.java:24`. The method is at `PlatformGroundTest.java:48` on
  `release-1.6.4` and on `163-integration`, and the assertion that fails is the `spawn + " is off its level"` compare at
  `:59` on both. Re-run once before you debug it; do not "fix" it in an unrelated lane.
- **There is no `src/main/resources/db` directory** in this repo — `src/main/resources` holds only `META-INF`,
  `log4j2.xml` and `soloMapling`. Any ticket that assumes the stock SQL ships with the jar is wrong; migrations live in
  `database/migrations/`.
- **Concurrent builds poison a suite.** Two agents compiling into one `target/` produce the `NoClassDefFoundError`
  storm described above. One build per worktree at a time.
- **The live box is the owner's.** `192.168.0.164`, unit `slumsms`, port 8485,
  `/opt/mapleroot/MapleRoot Full Repack/Server`, DB `buns-clean-db-1` (3309) and `/srv/slums-patch`: **no changes,
  deploys or restarts without the owner's go.** Reading live is allowed (`START-HERE.md` §3, owner, 2026-11-01) to
  debug a live issue or gather bot/economy stats — logs, files, the unit, and SELECT-only DB reads. Never read real
  players' passwords or hashes, PINs, session tokens, emails or IPs, and prefer aggregates over individual players.
  Never stop, restart or deploy anything, TEST included.

## Method rules learned the hard way

- **Cause before code.** Reproduce in a test that fails for the stated reason, then fix. "The line looks wrong" is not
  a finding; the merge record's lanes each carry a fail-before run.
- **A line number is branch-local.** Every audit in this hunt found the same expressions at different line numbers on
  `163-integration` versus `release-1.6.4` (`Character.java` by ~65 lines, `AbstractPlayerInteraction.java` by hundreds).
  Grep the symbol; quote the branch you verified on.
- **A ticketed claim can be stale.** F08 survived as a "defect" even though its own file had been rewritten. Open the
  file before you repeat a row.
- **Quote the aggregate, not the impression.** `Tests run: N, Failures: 0, Errors: 0` plus BUILD SUCCESS, or it did not
  happen.
- **Switches default OFF** and each one gets its `docs/release/<v>.conf` line, and the conf's `SERVER_SET` keys are
  checked against `ServerConfig.java` by `tools/release/stage`. A key with no field, or a field with no key, is a bug
  in the release file.
- **One card, one closer, one proof.** `EXTERNAL-AGENTS.md` sections 4-5: every card names its closer and the proof a
  lane session can copy straight into the release book.
- **Do not touch another worktree.** `/root/work/SlumsMS-164-release` and `/root/work/SlumsMS-163-integration` are
  other sessions' trees; read them, never edit, build or test inside them.
