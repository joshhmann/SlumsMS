# Site framework (1.6.1)

The plan is `STACK-PROPOSAL.md`, as the owner approved it: the pages stay generated by `tools/site/build.py`, Alpine.js
runs the live parts of the market, and Flask runs the services. Branch `site-161-framework`, started on 2026-10-27
from `site-160-theme`. Nothing here is on TEST or live yet.

## Services: Flask

- `tools/site/market_app.py` is the market service on Flask 3, from Ubuntu's `python3-flask` (3.0.2 on 24.04). There's
  no pip and no venv.
  - It keeps `market_service.py`'s contract: the same URLs under `/api/market/` (`me`, `board`, `cards`, `watch`,
    `alerts`, `posts`, ...), the same session cookie, the same JSON and status codes.
  - It imports that file's `Store`, so the rules and the game's inbox and outbox don't change.
- **Tests:** `tools/site/test_market_app.py` runs every HTTP test of the old service against the Flask app. It also
  checks:
  - the list of URLs matches;
  - a few answers are the same as the old service's, side by side.
- **New areas:** each one is a Blueprint registered in `create_app()`. The NX-meso exchange (ticket 113) goes in next to
  `market_routes()`. The app handles three things for every area:
  - **Sessions:** every URL except the ones in `OPEN` needs a sign-in.
  - **Writes:** `write_body()` checks the X-Slums header, the Origin, the size and that the body is a JSON object.
  - **Refusals:** `Refused(message, status)` becomes `{"ok": false, "error": message}`.
- **Running it:** `market_app.py` takes the same flags and environment as `market_service.py`, on the same port. It
  uses Werkzeug's threaded server on 127.0.0.1 behind nginx, and the log shows no addresses or cookies. To switch, the
  unit's command changes from `market_service.py` to `market_app.py`; switching back is the reverse.
- **Not done yet:**
  - the systemd unit and install.sh change;
  - `python3-flask` on 164;
  - `login_service.py`.

## Pages: Alpine.js live panels

- **Alpine:** `docs/site/assets/vendor/alpine-3.14.1.min.js`. It's alpinejs 3.14.1 from npm (MIT), sha256
  `358d9afbb1ab5befa2f48061a30776e5bcd7707f410a606ba985f98bc3b1c034`, pinned in `tools/site/test_vendor.py`. It's
  served from our own server, never a CDN.
- **The pattern:** `docs/site/assets/live.js` provides `x-data="live(url, seconds)"`. A panel:
  - polls a JSON URL and keeps its last good answer;
  - backs off on errors, up to 5 minutes;
  - stops at a 401 and shows "signed out";
  - pauses while the tab is hidden;
  - sends writes with the X-Slums header (`send(path, body)`).
  The usage is at the top of the file.
- **Tested:** headless Chromium on a stub server (not committed). It covered:
  - a good answer, then a 500: the data was kept and the retries waited longer each time;
  - recovery when the server came back;
  - a refused write: the error was shown and the header was sent;
  - a 401: the panel stopped polling.
- **Not wired into any page yet.** The first users will be the FM listings, the board, My market and the exchange.
- If the site ever gets a Content-Security-Policy without `unsafe-eval`, switch to Alpine's CSP build.
