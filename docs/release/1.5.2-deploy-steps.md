# 1.5.2: deploy steps outside the jar

Steps the 1.5.2 release needs that `docs/release/1.5.2.conf` and the generated `deploy.sh` do not do by
themselves (the release tools have no WZ-data step; 1.4.1 hand-wrote one into its `deploy.sh`). Whoever writes
1.5.2.conf / the 1.5.2 deploy: carry each item into the deploy, the release notes and the QA checklist. Add new
items below.

## 1. Server WZ: Zipangu (Mushroom Shrine) quest dates

What: MapleRoot's server `Quest.wz/Check.img.xml` puts an end date of 2000-01-02 on quests 4300-4305, 4307, 4308
(start) and 4309 (completion), so the server refuses them. Stock Cosmic and MapleLegends have no date. The step moves
the 9 dates to 2099-12-31 (`tools/data-align/zipangu-quest-dates.tsv`). Owner approved 2026-10-25.

The server reads the WZ at boot, so the change takes effect at the restart the deploy does anyway. Each row only
changes a file that still holds the old value; a second run changes nothing.

TEST (`/opt/mapleroot-dev/persistence-test/Server`), before or with the 1.5.2 test deploy:
```
cd <1.5.2 checkout>
python3 tools/data-align/wz_set_values.py --wz /opt/mapleroot-dev/persistence-test/Server/wz \
  --tsv tools/data-align/zipangu-quest-dates.tsv --column new_value            # expect: dry run: 9 value(s) in 1 file(s), 0 skipped
python3 tools/data-align/wz_set_values.py --wz /opt/mapleroot-dev/persistence-test/Server/wz \
  --tsv tools/data-align/zipangu-quest-dates.tsv --column new_value --apply    # backup: Server/wz-backup-<UTC>/
```
(run it on 164; the script and TSV are in the staged `tools/` folder.) Then restart TEST (`tools/ops/deploy-test`
does).

Live (owner's go, during the 1.5.2 deploy while the server is stopped or just before it): the same two commands
with `--wz "/opt/mapleroot/MapleRoot Full Repack/Server/wz"`, from the staged release's `tools/data-align/`. The
dry run must say `9 value(s) in 1 file(s), 0 skipped` (not checked against live's files: agents don't read live;
TEST's Check.img.xml md5 is `b2b285229620985b8e784a342636065e` for comparison). Rollback: copy `Server/wz-backup-<UTC>/Quest.wz/Check.img.xml`
back and restart; nothing else reads it.

Check on TEST with a real client (not done yet): a level 20+ character in Zipangu talks to Kino Konoko (NPC 9110002,
Mushroom Shrine 800000000) and can accept "Kino Konoko's Concern" (4300). If the client does not offer it, the client's own
Quest.wz has the same 2000 date and needs a client data patch too; the server side is then harmless but not enough.

Release notes line: "The Mushroom Shrine quests in Zipangu (Kino Konoko, Hanako...) can be started again."

Test: `python3 -m unittest discover -s tools/data-align -p 'test_*.py'` (applies the TSV to a temp copy of the
server's Check.img.xml; needs `wz/`, skips without it).
