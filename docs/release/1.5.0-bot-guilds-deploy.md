# 1.5.0 deploy notes: bot guilds and partying with players (branch `bots-guilds-150`, ticket 50 B/C)

For the rc3 test install first, then live with the owner's go. Nothing here has been run on a server yet.

## Migration (stop the game, back up first; idempotent, with a rollback)

`database/migrations/014-bot-guilds.sql`: tables `botguild` (one row per bot-run guild: vibe, rival, size) and
`botguildmember` (one row per bot in any guild). Ledger id `014-bot-guilds`. Rollback:
`014-bot-guilds.rollback.sql` (deletes the bot guilds' stock `guilds` rows and their BBS posts, makes players who
joined one guildless, drops both tables).

Without it the server runs as before: no bot guild is founded and a bot that joins a player's guild is a member only
until a restart (one warning in the log: "is migration 014-bot-guilds applied?").

**What happens at the first start with it:** about a minute after boot, once 40+ roster bots exist, the server founds
the ten bot guilds itself (`GuildPlan.SPECS`: Lionheart, Moonlight, GoldenBazaar, SlumLords, Nightfall, MapleLeaf,
RedSnails, Ironclad, Sprouts, DawnRunners; 220 members at full roster, fewer on a small one - half the roster at
most). It writes 10 stock `guilds` rows (so those names are taken for players) and the member rows. A name a player
guild already holds is skipped. It runs once: with any bot guild present it never founds again.

## Config

No `config.yaml` keys (config is strict). Every tunable is a `-Dsolomapling.guilds.*` property with a safe default:

| Property | Default | What |
|---|---|---|
| `enabled` | true | false = no bot guild behaviour at all (members still load into guild lists) |
| `seed` | true | false = never found the bot guilds automatically (`!botguild form` still works) |
| `chatterMinutes` / `chatterChance` | 8 / 0.6 | idle guild chat: one try per guild per 8 min, only with a real member online |
| `answerSeconds` / `answerChance` / `chatChance` | 20 / 0.6 / 0.25 | a player's guild line: one bot answers per 20 s unless named; chance for a question/greeting, other lines |
| `gzChance` | 0.5 | a bot guildmate says gz on a real member's level-up |
| `inviteAccept` / `softShare` | 0.95 / 0.5 | a friend bot takes a player's guild invite; past this share of bots it gets pickier |
| `applyAccept` | 0.8 | a bot guild leader's yes to a neutral player above the level floor |
| `ignoreDays` | 21 | a bot in a player-led guild quits after this many days without attention |
| `quitCheckMinutes` | 10 | quit checks per guild with a real member online |
| `partyNeutral` / `partyGuildmate` | 0.3 / 0.9 | an unasked party invite from a real player: neutral bot / guildmate (friends 1, rivals 0) |
| `partyMinutes` | 10 | a bot guild forms at most one grinding party per 10 min |
| `recruitHours` / `whispersPerHour` | 6 / 4 | recruit rounds per guild; world cap on recruit whispers (a player is whispered at most every 3 days) |
| `jabMinutes` / `megaJabHours` / `claimMinutes` | 15 / 8 / 45 | rival pairs: map jab, megaphone jab, grind-map claim |
| `bossEveryHours` / `bossGapHours` / `bossChance` / `bossMinGroup` | 8 / 2 / 0.25 / 3 | staged boss runs: per guild, world gap, roll per 30 min, crew floor |
| `gatherMinutes` / `runMinutes` / `bossGp` | 4 / 25 / 150 | staged run timing; guild GP on a clear |

Megaphones all go through `BotMegaphoneGate`/`WorldEventMegaphones` (the world cap and `@quiet megaphones` hold).
