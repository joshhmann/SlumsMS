# 1.6.0: `@weblogin` (website sign-in from the game)

Players type `@weblogin <CODE>` (the 6-character code shown on the website's `/login/` page) to sign the browser
in to the database and Slums Market. Contract: `docs/design/site-login-contract.md`. It shows up in `@help`
(Common list) like every other player command.

- The command is **off by default**. With no `-Dslums.weblogin.dir` it replies "Website sign-in isn't available
  right now."
- **Live only, once the owner installs the login service on 164**, add to the live start line:
  `-Dslums.weblogin.dir=/var/lib/slums-login` (approvals go to `<dir>/approvals/<CODE>.json`; `<dir>/revoked.txt`
  lists account ids refused, one per line). Optional `-Dslums.weblogin.group=` (default `slums-login`).
- **TEST must never use the live directory.** TEST and live share a host, so a TEST account could otherwise sign
  someone into the live website. For testing set a scratch dir, e.g. `-Dslums.weblogin.dir=/tmp/weblogin-test`.
- Limits: 5 per minute per account, codes upper-cased, bots refused, disk errors are logged and the player is
  told to try again. File mode 0640; if setting the group fails it is logged once and the command carries on.

QA: with a scratch dir set, `@weblogin K7Q4ZP` creates `approvals/K7Q4ZP.json`; `@weblogin nope` says the code
doesn't look right; a sixth use within a minute says to slow down; with the property unset it says unavailable.
