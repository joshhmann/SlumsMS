# 1.5.0 gachapon machines: client data (for the client lane)

**Short answer: the client needs no change.** The six new machines are server-spawned NPCs (`plife` rows,
migration `database/migrations/013-gachapon-machines.sql`). The server sends `SPAWN_NPC` /
`SPAWN_NPC_REQUEST_CONTROLLER` for them on map entry, exactly as for `!pnpc`. A v83 client draws any NPC whose id is
in its `Npc.wz` and does not need the map's `Map.wz` life list to contain it.

What the client must have (and the server's WZ dump has): `Npc.wz/9100101.img`, `9100102`, `9100103`, `9100104`,
`9100105` and `9100109`, and their names in `String.wz/Npc.img` ("Gachapon"). If the client's `Npc.wz` is the same
build as `/root/work/bake/wz`, there is nothing to do.

`f` = 0 (faces left, the default), `rx0` = x + 50, `rx1` = x - 50, `hide` = 0.

## Only if you choose to bake them into the client too (optional, not needed)

Add a `life` entry to each map image above, for example for Ellinia (`Map.wz/Map/Map1/101000000.img`, next free index
under `life`):

```
<imgdir name="N">
  <string name="type" value="n"/>
  <string name="id" value="9100101"/>
  <int name="x" value="1120"/>
  <int name="y" value="288"/>
  <int name="fh" value="1107"/>
  <int name="cy" value="288"/>
  <int name="rx0" value="1170"/>
  <int name="rx1" value="1070"/>
</imgdir>
```

If you do, the **server** WZ would then also load it, and with the `plife` row the map would have two machines: drop
migration 013 (or run its rollback) when the client and the server WZ carry the entries.

## Check on a real client

- `!warp 101000000` (and the other five): the Gachapon machine stands on the ground at the spot above, it is not
  floating or under the floor, and clicking it opens the 1.5.0 Gachapon dialog for that town.
- The minimap may or may not show it; note what you see.
