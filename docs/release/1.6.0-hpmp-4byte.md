# 1.6.0: HP and MP past 30,000 (4-byte HP/MP)

Branch `160-hpmp-int` (server half). The client half is slums.dll **build 10600+**.

## Release rule

**1.6.0 must ship with `MIN_CLIENT_BUILD=10600` and the 4-byte client together.** When `docs/release/1.6.0.conf` is
written, it must say `MIN_CLIENT_BUILD=10600`; the test server's `config.yaml` needs `MIN_CLIENT_BUILD: 10600` under
`server:` before it runs a jar from this branch with real clients.

The server writes the nine fields below as 4 bytes for every client; there is no per-client switch. A client older
than 10600 reads them as 2 bytes, so every packet after the first HP field is misaligned: wrong stats, a broken
character list and probably a crash on login or the first map change. The ClientVersionGate (CP 0x3738 build
stamp, `ServerConfig.MIN_CLIENT_BUILD`) refuses those clients at login, which is why the gate and the client must go
out in the same release, client first (`stage-client`/`publish-client`, then the server deploy).

Two traps: `MIN_CLIENT_BUILD` defaults to 0 (gate off), so a 1.6.0 jar on a server whose config does not set it
serves old clients broken packets; and `MIN_CLIENT_BUILD_GM_BYPASS: true` would let a GM on an old client in to the
same broken stream. Keep the bypass false (the default) for 1.6.0, or make sure every GM runs 10600+.

## Wire contract (server writes `writeInt`, client reads `Decode4`)

| # | Packet | Field |
|---|---|---|
| 1-4 | GW_CharacterStat (`PacketCreator.addCharStats`: SET_FIELD char data, cash shop entry, char list, view-all-char, new char entry) | HP, MaxHP, MP, MaxMP |
| 5 | SET_FIELD plain map change (`getWarpToMap`, both variants) | HP after map(4) portal(1) |
| 6-9 | STAT_CHANGED (`updatePlayerStats`) | masks 0x400 HP, 0x800 MaxHP, 0x1000 MP, 0x2000 MaxMP |

Unchanged: party door record (party result 0x25 shorts), remote ranged attack shot point, CUserRemote OnReceiveHP
(party HP, already int+int), and the incoming CP 0x59 heal-over-time packet (2-byte HP/MP heal).

## Cap

HP, MaxHP, MP and MaxMP (base, and with gear and buffs) are capped at **99,999** (`GameConstants.MAX_HPMP`),
up from 30,000. AP into MaxHP/MaxMP stops at the cap; `!maxstat` sets 99,999.

## QA (real client, test server)

1. GM 3+: `!setmaxhp 50000` (or `!setmaxhp 50000 60000` for different MP). It sets base MaxHP/MaxMP and refills.
2. Check the HP/MP bars and the stat window (50,000 / 60,000), change map, change channel, log out and back in:
   the character list and the game show the same numbers.
3. Take damage and drink a potion: HP moves correctly above 32,767. Hyper Body on top stays at or below 99,999.
4. `!setmaxhp 99999`: bars show 99,999. `!setmaxhp 100000` clamps to 99,999.
5. An old client (build below 10600) is refused at login with the update message.
