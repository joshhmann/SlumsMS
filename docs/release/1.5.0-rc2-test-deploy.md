# 1.5.0-rc2 onto the test server (slums-persistence-test)

`test-1.5.0-rc2` = `test-1.5.0-rc1` + `economy-gacha-150` (gachapon per town, ticket 56B bot wealth ceiling, six town
machines) + `bots-affinity-150` (ticket 58: affinity and `@botdrama`, earned speed, bot couples, Amoria weddings).
SLUMSMS_VERSION `1.5.0-rc2`. Not deployed: the owner decides what goes on test.

The script is `deploy-test-150rc2.sh` (staged next to the build in `$T/rc150b/`), modelled on rc1's
`/opt/mapleroot-dev/persistence-test/rc150/deploy-test-150rc1.sh`. It stops on the first failed check; every check
before "stop" changes nothing.

## What it does

| Step | Detail |
|---|---|
| Pre-checks | jar sha256 prefix, `scripts.tar`/`srcdata.tar` present (and `gachapon-pools.yaml` inside), all six migration files, no earlier backup in `rc150b/backup`, test is on rc1's config (`channels: 5`, no `MIN_CLIENT_BUILD`, `start-test.sh` has `-Dslums.qa=true`), ledger exactly `001..010` |
| Stop + backup | `systemctl stop slums-persistence-test`; `mysqldump mapleroot_persist` -> `backup/mapleroot_persist.sql.gz` (gzip-tested); `backup/server-runtime.tgz` (jar, config.yaml, scripts, src/main, cashshop); `backup/start-test.sh`; `backup/bot-nav.tgz` (the full nav cache, before the clean-up) |
| Migrations | `011-bot-affinity` (tables `botaffinity`, `botdrama`), `012-bot-couples` (`botcouple`), `013-gachapon-machines` (12 `plife` rows: six towns x worlds 0/1), in that order. Each must write its ledger row; the ledger must then be `001..013` |
| Data | `Cosmic.jar` -> `target/`; `scripts.tar` (`scripts/npc/gachapon.js`, `gachaponInfo.js`, `gachaponRemote.js`, `9201000.js`); `srcdata.tar` (every non-.java file under `src/main`: `soloMapling/Gachapon/gachapon-pools.yaml`, `AffinityDialogue`/`CoupleDialogue`/`MegaphoneDialogue`/`WorldEventDialogue.yaml`, `worldevents/WorldEvents.yaml`) |
| Nav cache clean-up (once) | In `Server/cache/bot-nav/v68` (the graph-version folder): delete graph files `[0-9]*-s*-j*.bin` except `*-s100-j100.bin` / `*-s100-j100-ss.bin`, and the same non-base keys under `deep/` (`.json`). `observed/` stays. Backup is `backup/bot-nav.tgz` (delete after a quiet week). Why: `docs/release/1.5.0-bots-affinity-deploy.md` |
| Start + checks | `bash start-test.sh`; waits for "is now online"; prints the boot lines, warns on a missing `SlumsMS v1.5.0-rc2` line or any "is migration 01x applied?" warning, counts ERROR/Exception lines |

No `config.yaml` change (rc1 set channels 5 / CHANNEL_LOAD 105; `MIN_CLIENT_BUILD` stays unset on test so the
current test client logs in). No catalogue change. `start-test.sh` stays as rc1 installed it.

## Staging (workstation, before running)

From the `test-1.5.0-rc2` checkout at the built commit, into `$T/rc150b/` on the test host:

```sh
git ls-files scripts | tar --owner=0 --group=0 -cf scripts.tar -T -
git ls-files src/main | grep -v '\.java$' | tar --owner=0 --group=0 -cf srcdata.tar -T -
# plus target/Cosmic.jar, deploy-test-150rc2.sh and migrations/{011-bot-affinity,012-bot-couples,013-gachapon-machines}{,.rollback}.sql
```

## Rollback

```sh
systemctl stop slums-persistence-test
for m in 013-gachapon-machines 012-bot-couples 011-bot-affinity; do db < $RC/migrations/$m.rollback.sql; done
tar -xzf $B/server-runtime.tgz -C $SRV
rm -rf $SRV/cache/bot-nav && tar -xzf $B/bot-nav.tgz -C $SRV/cache
bash $T/start-test.sh
```

The rollbacks drop every affinity tie, `@botdrama` opt-out, couple and the six machines. For an exact return to the
moment of the stop, restore `backup/mapleroot_persist.sql.gz` instead of running them.

## Migration numbering

Both branches had added an 011. Renumbered on rc2: `011-bot-affinity`, `012-bot-couples`, `013-gachapon-machines`
(the gachapon file, its rollback, its ledger id and every doc/test reference). The ledger id is the file stem
(`tools/release/lib.sh` `ledger_id` reads the INSERT); live is at `010-color-prism` and test is expected there too
(rc1 had no migrations); if an old `011-gachapon-machines` row was ever written on a scratch DB, the ledger pre-check
aborts and that row must be removed by hand (its rollback under the old id) first. Live: `docs/release/1.5.0.conf`.
