# Fishing

## Purpose

Timed fishing replaces the upstream meso-bait fishing with a session service: a character seated on a chair on one of three fishing maps waits 90 seconds, then receives exactly one item from a fixed five-item table, and keeps waiting for another 90 seconds while seated. The same service is shared by players and by the bot life brain (`FISH` activity), so bots fish with the identical timer, roll and inventory path. Everything is off unless two JVM flags are set, and when the new mode is on the legacy meso/EXP/rare pool is bypassed entirely rather than run alongside it.

## How it works

1. **Admission.** `Character.sitChair(int itemId)` requires `isLoggedinWorld()`, `itemId >= 1000000` and no current chair; it calls `setChair(itemId)`, broadcasts `PacketCreator.showChair`, and then `GameFishing.start(this)` (src/main/java/client/Character.java:9096-9106). `GameFishing.start` refuses unless `FishingPolicy.rewardsEnabled()` (both flags) and then asks the shared service for a session (src/main/java/soloMapling/fishing/GameFishing.java:69-71).
2. **Eligibility snapshot.** `FishingSessions.start(actor, now)` rejects a null/ineligible position or a chair outside 3010000-3019999 with `REFUSED`, returns `ALREADY_FISHING` for the same actor identity, cancels a stale actor with a different identity, takes a slot under the limit (256), and stores the session with `next = now + 90_000` (src/main/java/soloMapling/fishing/FishingSessions.java:51-68, limit at src/main/java/soloMapling/fishing/GameFishing.java:16). The `Position` recorded is the actor's current world, channel, map object, x, y, chair and `eligible` bit (src/main/java/soloMapling/fishing/FishingSessions.java:19).
3. **What "eligible" means.** `GameActor.position()` returns `eligible = rewardsEnabled && online && alive && map != null && point != null && isFishingArea(map) && point.y > 0 && seatFishes(chr) && hasChair(chr)` and no event instance, trade, shop, player shop or hired merchant, where "online" for a bot means `CharacterStorage.getBotById(id)` returns the same character with `getRunning()` true, and for a player means `chr.isLoggedinWorld()` (src/main/java/soloMapling/fishing/GameFishing.java:91-104). `seatFishes` allows any chair for a player but only item 3011000 for a bot (src/main/java/soloMapling/fishing/GameFishing.java:57-60).
4. **Tick.** Every 10 s `World.runCheckFishingSchedule()` calls `GameFishing.tick(id)` → `FishingSessions.tickWorld(world, now)` → `tick(id, now)` for every session whose origin world matches (src/main/java/net/server/world/World.java:2136-2137, src/main/java/soloMapling/fishing/FishingSessions.java:91-93). `now` is `System.nanoTime() / 1_000_000`, i.e. a monotonic per-JVM clock, not wall time (src/main/java/soloMapling/fishing/GameFishing.java:35).
5. **Cancellation check.** Inside the per-session `ReentrantLock`, a tick cancels (`Tick.CANCELLED`) when the clock ran backwards, `next` would overflow, the position is no longer eligible, or any of world/channel/map identity/x/y/chair differ from the origin snapshot (src/main/java/soloMapling/fishing/FishingSessions.java:99-106). Anything that moves, stands, dies, changes instance, trades or disconnects therefore ends the session at the next tick — standing is caught twice, immediately by `setChair` (src/main/java/client/Character.java:9158) and again by the snapshot diff.
6. **Wait or catch.** `s.last = now`; if `now < s.next` the tick returns `WAIT` (src/main/java/soloMapling/fishing/FishingSessions.java:107-108). Otherwise the timer is re-armed **before** any inventory effect — `s.next = now + INTERVAL_MS` at :110 with the comment "A stalled tick never catches up in a burst" — so a server stall pays at most one catch, not a backlog.
7. **Roll.** `roll.applyAsInt(total)` with `total` the summed reward weights (100), a `ThreadLocalRandom` bound function (src/main/java/soloMapling/fishing/GameFishing.java:16-17); a result outside `[0, total)` throws `IllegalArgumentException("fishing roll outside policy")` which the `catch (RuntimeException)` converts to session removal + `Tick.FAILED` (src/main/java/soloMapling/fishing/FishingSessions.java:112-113, :119-120). The weighted walk picks the first reward whose weight exceeds the remaining value (src/main/java/soloMapling/fishing/FishingSessions.java:114-115).
8. **Reward.** `GameActor.give` calls `InventoryManipulator.addById(chr, itemId, (short)1, null, -1, -1)` on the `Character` overload directly, because `BotClient.getPlayer()` is null (src/main/java/soloMapling/fishing/GameFishing.java:105-109, overload at src/main/java/client/inventory/manipulator/InventoryManipulator.java:72-88). A `false` return means the bag is full: the actor is told "Make room in your inventory to keep your next catch.", the tick returns `FULL_BAG`, and the timer has already been spent — the catch is lost, not retried (src/main/java/soloMapling/fishing/FishingSessions.java:116).
9. **Catch feedback.** `GameActor.caught` increments the bot or player catch counter, calls `Achievements.onFish(chr)`, sends `Effect/BasicEff.img/Catch/Success` to the angler and broadcasts it to the map, drops "Caught <name>.", and writes a QA log line `FISHING CAUGHT item=… quantity=1 sequence=…` (src/main/java/soloMapling/fishing/GameFishing.java:111-119; effect packets at src/main/java/tools/PacketCreator.java:6110 and :6118).
10. **Repeat.** The session stays; the next catch is another 90 s away, and only `setChair`, movement, death, disconnect, a trade/shop/window, or world shutdown ends it (src/main/java/soloMapling/fishing/FishingSessions.java:69-72, :80-90).
11. **Shutdown.** `World.dispose` calls `GameFishing.stopWorld(id)` → `cancelWorld` before cancelling the ticker (src/main/java/net/server/world/World.java:2250-2253).
12. **Legacy bypass.** When `FishingPolicy.enabled()` is true, `runCheckFishingSchedule` returns right after ticking the new service, with the comment "Never mix the legacy meso/EXP/rare pool into timed fishing." (src/main/java/net/server/world/World.java:2138-2140). Otherwise the old path runs: `Fishing.fetchFishingLikelihood()` then one `Fishing.doFishing` per registered attempter (src/main/java/net/server/world/World.java:2141-2155), fed by dropping mesos into water (src/main/java/net/server/channel/handlers/MesoDropHandler.java:72 → src/main/java/client/Character.java:7604-7609, which itself refuses to register while the new mode is on).
13. **Bot chair placement.** `BotGeneration` calls `BotFishingChairs.ensure(bot)` at the end of decoration/restore, before the spawn choreography (src/main/java/soloMapling/ArtificialPlayer/BotGeneration.java:260-262). `ensure` locks the SETUP bag, skips if the bot already owns 3011000 or the bag is full, and otherwise adds one (src/main/java/soloMapling/fishing/BotFishingChairs.java:51-69). Only bots whose roster slot passes `drawn(slot)` **and** whose leading Bartle type is EXPLORER or SOCIALIZER get one (src/main/java/soloMapling/fishing/BotFishingChairs.java:28-45); the draw is a splitmix64-style hash of the slot with `Long.remainderUnsigned(z, 20) == 0`, so nothing is stored and the result is stable across restarts (src/main/java/soloMapling/fishing/BotFishingChairs.java:21-39). Slots come from `SocialProfile.slotOf(id)` = `id - BOT_ID_BASE` for bots (src/main/java/soloMapling/ArtificialPlayer/BotLifeSystem/SocialProfile.java:109-112), and the type from the quadrant of the seeded point (`leading()`, src/main/java/soloMapling/ArtificialPlayer/BotLifeSystem/SocialProfile.java:168-171).
14. **Bot fishing loop.** The life brain offers `FISH` only when `GameFishing.choosable` holds — both flags, an owned chair, and a reachable destination — where the destination is the current map if it is already a fishing map with `y > 0`, else 120010000 (src/main/java/soloMapling/ArtificialPlayer/BotTypes/TrainingBot.java:983, src/main/java/soloMapling/fishing/GameFishing.java:36-40, :65-67). On arrival the bot reserves a town slot, settles, waits until it stops moving, then `MovementCommands.botSitChair(chr, GameFishing.chairToUse(chr))` and `GameFishing.start` (src/main/java/soloMapling/ArtificialPlayer/BotTypes/TrainingBot.java:1073-1079, :1311-1317; seating at src/main/java/soloMapling/ArtificialPlayer/BotMovementSystem/MovementCommands.java:513-522). `chairToUse` returns 3011000 for any character that owns it, 0 for a bot without it, and otherwise the first 301xxxx item a player owns (src/main/java/soloMapling/fishing/GameFishing.java:46-54). A cancelled session is never silently restarted inside the same dwell (`lifeFishingStarted` guard, src/main/java/soloMapling/ArtificialPlayer/BotTypes/TrainingBot.java:1307-1309); leaving the activity cancels and stands the bot up (src/main/java/soloMapling/ArtificialPlayer/BotTypes/TrainingBot.java:559-565), as does `stopScheduledTask` (src/main/java/soloMapling/ArtificialPlayer/BotTypes/TrainingBot.java:3073-3074).
15. **Starter chairs.** `CharacterFactory.createNewCharacter` appends both chairs to the creation recipe (src/main/java/client/creator/CharacterFactory.java:126-127 → src/main/java/soloMapling/fishing/StarterChairs.java:31-34), and `PlayerLoggedinHandler` runs `StarterChairs.onLogin` before the char-info packet (src/main/java/net/server/channel/handlers/PlayerLoggedinHandler.java:241). `onLogin` gives both chairs only to a player character that owns neither, has 2 free SETUP slots, and has no `area_info` row 29151, then writes that row as the once-only mark; a character that already owns either chair is just marked (src/main/java/soloMapling/fishing/StarterChairs.java:36-70). `noticeIfWaiting` tells a character with a full bag to free two slots and log in again (src/main/java/soloMapling/fishing/StarterChairs.java:73-79).

## Invariants

- **One item per 90 s per actor, and the timer is spent before the grant** — `s.next` is advanced before `give`, so a full bag costs the timer and a stalled server never pays a burst (src/main/java/soloMapling/fishing/FishingSessions.java:109-116; asserted by `lateTimersNeverPayACatchUpBurstAndFullBagsSpendTheirAttempt`, src/test/java/soloMapling/fishing/FishingSessionsTest.java:34).
- **A session only pays where it started** — world, channel, map identity, x, y and chair must all match the origin snapshot (src/main/java/soloMapling/fishing/FishingSessions.java:101-104).
- **Two ticking threads cannot double-pay** — each session has its own `ReentrantLock` and re-reads `sessions.get(id) != s` under it (src/main/java/soloMapling/fishing/FishingSessions.java:97-99; `overlappingTicksCannotGrantTheSameCatchTwice`, src/test/java/soloMapling/fishing/FishingSessionsTest.java:67).
- **The slot budget is exact** — admission is a CAS loop on `slots` and removal decrements only when `sessions.remove(id, s)` succeeds (src/main/java/soloMapling/fishing/FishingSessions.java:61-63, :90; `boundedAdmissionsAndWorldCleanupReleaseTheirSlots`, src/test/java/soloMapling/fishing/FishingSessionsTest.java:58).
- **A reconnect cannot be cancelled by its predecessor** — identity is the `Character` object, so the old actor's late cleanup removes nothing (src/main/java/soloMapling/fishing/FishingSessions.java:56-60, :81-86; `aReconnectReplacesTheOldActorAndItsLateCleanupCannotCancelTheNewOne`, src/test/java/soloMapling/fishing/FishingSessionsTest.java:102).
- **Bots fish only from the Fishing Chair, players from any chair** — src/main/java/soloMapling/fishing/GameFishing.java:57-60.
- **Bot chair ownership is deterministic and never re-given** — hash of the slot, one `ensure` per bag, and `SaleRules` refuses to sell it (src/main/java/soloMapling/fishing/BotFishingChairs.java:33-39, :61; src/main/java/soloMapling/Economy/SaleRules.java:89-90).
- **The starter grant is once per character** — keyed on the `area_info` 29151 row, not on the items, so a sold or dropped chair is not replaced (src/main/java/soloMapling/fishing/StarterChairs.java:56-65; `loginGrantsBothOnceAndASoldChairIsNotGivenAgain`, src/test/java/soloMapling/fishing/StarterChairsTest.java:26).
- **Nothing is enabled by default** — both flags default false and the whole path short-circuits before touching a `Character` (src/test/java/soloMapling/fishing/GameFishingTest.java:20-27, `verifyNoInteractions(chr)`).
- **The legacy pool never runs beside the new one** — src/main/java/net/server/world/World.java:2138-2140.
