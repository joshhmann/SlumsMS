# Economy (bots, market, NX exchange, NX desk, site export)

## Purpose

One lane owns every number the world's money passes through: what a bot asks for an item, what a player gets for selling one, what a shop charges and taxes, what the website publishes about prices, and how NX and mesos change hands between players. It is three machines in one package: a **price board** fed by real trades (`src/main/java/soloMapling/Economy/PriceBook.java:27-54`), a **volatile market** of item tickers driven by trader bots, world events and rumours (`src/main/java/soloMapling/Economy/exchange/volatility/MarketVolatility.java:25-32`), and an **NX ⇄ meso exchange** with an order book and, since 1.6.3, an NX house desk (`src/main/java/soloMapling/Economy/exchange/Exchange.java:38-63`, `src/main/java/soloMapling/Economy/exchange/Desk.java:1-30`). Almost all of it is bot-facing or site-facing; the only player-visible surfaces are `@nx`, the `@exchange` NPC, and the website pages that read its files.

## How it works

### 1. Exchange: a player places an NX or item order (book) and it fills

1. `@nx buy 500 4.5k` is parsed by `ExchangeChat.handle` (`src/main/java/soloMapling/Economy/exchange/ExchangeChat.java:43`); NX prices are typed per 1 NX and multiplied by 1,000 internally (javadoc `:28-31`).
2. The chat layer calls `Exchange.preview` (`src/main/java/soloMapling/Economy/exchange/Exchange.java:831`, `:836`). Preview runs the same guards as a place — `!recovered` → `UNAVAILABLE` (`:838-840`), bot account → `BAD_REQUEST` (`:841`), `halted` → `HALTED` (`:844-846`), `desk != null && Ticker.NX` → `deskPreview` (`:847-849`) — then `validate` (`:1670-1703`: request id ≤ 64 chars, ticker open, qty inside min..max in lots, price inside min..max, BUY `buyTotal` ≤ `Integer.MAX_VALUE`), `priceBand` (`:324`) and `limits` (`:1706-1730`: per-ticker open count `LIMIT_OPEN`, per-ticker daily count `LIMIT_DAY`, one account-wide cooldown `COOLDOWN`). Nothing moves; the token is remembered in `pending` for `confirmMs` (`src/main/java/soloMapling/Economy/exchange/ExchangeConfig.java:59-63`, 60 s).
3. `@nx confirm` → `Exchange.confirm` (`:943-968`): `halted` check, token lookup and expiry (`TOKEN_EXPIRED`), account match, then `place`.
4. `Exchange.place` (`:658-721`) re-checks every guard in a fixed order: recovered (`:660`), bot (`:663`), halted (`:666`), the desk's NX refusal (`:669-671`), `validate` (`:672`), idempotency via `store.byRequest(rid)` (`:677-687`, a foreign account on the same id is `DUPLICATE`), `priceBand` (`:689`), `limits` (`:693`), item `sellCap` (`:697`, `:2861-2881`: filled + resting item-sell mesos since UTC midnight against `-Dslums.exchange.items.sellCapMesosPerDay`, code `ITEMS_CAP`).
5. Funding the order splits three ways: a live character → `placeLive` (`:745-781`) takes the escrow out of `LiveWallet` under the character's save lock, saves, then writes the order; a logged-out character selling an item from the site → `placeBag` (`:799-823`) reads the bags from the DB through `OfflineBag`, takes in memory and writes the reduced inventory **inside the order's own transaction** ("the database holds the items either in the bags or in the escrow, never both", `:793-798`); an offline account otherwise → `collectQuietly` then `placeOrder` (`:720`).
6. `placeOrder` (`:1766-1861`) applies `outOfWindow` to *every* order including house regulars (`:1770-1775` — a fill trades at the resting price, so this keeps fills inside the hard window too), copies the book and the row map for rollback (`:1783-1784`), calls `OrderBook.place` (`:1786`), picks the escrow source bucket (`:1792-1796`: HOUSE for regulars, the bot PURSE for a bot NX sell, BOT for a bot, the character's WALLET for a buy or a per-character item sell, the account's WALLET for NX), posts `PLACE source → ESCROW` (`:1799`), reserves the buyer's fee into `Bucket.feeHold(orderId)` (`:1801-1805`), settles each fill (`:1809-1814` → `settle`), releases closed orders (`:1815-1817` → `release`), commits one `Batch` (`:1821-1825`) and rolls the book back on store failure (`:1826-1830`).
7. `OrderBook.place` (`src/main/java/soloMapling/Economy/exchange/OrderBook.java:191-258`) is a pure price-time matcher: best price then lowest seq (`bids`/`asks` at `:174-176`), the price cross check at `:209`, expired makers released without filling (`:214-222`), self-trade cancels the taker remainder (`:223-226`), `q = min(nxLeft)` at `:227`, mesos at the **resting maker's** price (`:228`, `:237`).
8. `settle` (`src/main/java/soloMapling/Economy/exchange/Exchange.java:1864-1889`) writes the four legs of a fill: quantity `ESCROW(sell) → ownerBucket(buy)` (`:1868-1871`), the seller's mesos `ESCROW(buy) → PAYOUT(character)` or `HOUSE` for a regular (`:1872-1878`), the seller-side fee to `Bucket.fees()` (`:1879-1881`), the buyer-side fee from its reserve capped at what is left (`:1882-1886`), and the `FillRow` row (`:1887-1888`).
9. `release` (`:1892-1905`) returns a closed order's remaining escrow and fee reserve to its owner's PAYOUT (or HOUSE). Every posting is one append-only `exchange_ledger` row (`src/main/java/soloMapling/Economy/exchange/Ledger.java:87-109`), applied by `JdbcExchangeStore.apply` (`src/main/java/soloMapling/Economy/exchange/JdbcExchangeStore.java:141-260`): one transaction, every WALLET account locked `FOR UPDATE` in id order (no deadlock), non-live accounts required to be logged out (`lock`, `:116-131`), item legs only through the batch's own live character or its offline bag (`:155-175`).
10. Delivery. NX and mesos land in the owner's `PAYOUT` bucket; `tick` then runs `collectAll` (`src/main/java/soloMapling/Economy/exchange/Exchange.java:2051-2066`) every poll: live accounts through `collectLive` (`:2097`), offline accounts `collectQuietly` (`:2078`) — `Why.COLLECT` postings move PAYOUT into the wallet row. Items are a separate pass (`collectItemsLocked`, `:2167-2215`) because they need bag room; a character with a full bag is nagged at most every 10 min (`roomNagged`, `:2184-2192`) and a half-done item payout halts the exchange (`:2200-2207`).
11. Site publication. `ExchangeService.Runner.tick` (`src/main/java/soloMapling/Economy/exchange/ExchangeService.java:180-203`) then rewrites `exchange-responses.json` (only if something was answered, `:187-190`), `exchange-book.json` (`:191`), `exchange-tickers.json` (`:192`), `exchange-history.json` (`:193`) and `nx-desk.json` (`:196-202`) through `BoardFiles.write` (temp file in the outbox, mode 0640, `ATOMIC_MOVE`, `src/main/java/soloMapling/Economy/board/BoardFiles.java:33-56`).

### 2. Exchange: cancel, expiry, and the order that never comes back

1. `cancel` (`src/main/java/soloMapling/Economy/exchange/Exchange.java:1951`) and `closeOrders` (`:1974`) run the same `release` path as a fill's remainder; a cancelled SELL returns the item to PAYOUT, not to a bag, until a collect.
2. `expire` (`:2011-2048`) closes every non-regular order past `expiresAt`, committing the releases in one batch and rolling the book back on failure (`:2019`, `:2036-2038`).
3. `recover` (`:482-583`) at boot rebuilds the books from the store, reconciles every stored exchange balance against `exchange_ledger` sums (`reconcile`, `:607`; `Ledger.balances` at `src/main/java/soloMapling/Economy/exchange/Ledger.java:113-125`), and **halts on any mismatch, auto-fixing nothing** (`:570-580`). After a clean reconcile it cancels and refunds every open NX order the hard window now forbids (`cancelClamped`, `:585-605`).
4. `halt` (`:3021-3028`) stops new orders, fills, expiry and payouts and clears every preview token; `resume` (`:3033-3052`) with the desk on also cancels and refunds every resting NX order (`cancelNxBook`, `:1506`) because the NX book is off in desk mode.
5. A post-commit failure anywhere in the money path halts rather than continues: `halt(` call sites at `:576`, `:578`, `:769`, `:788`, `:813`, `:1194`, `:1238`, `:1246`, `:1349`, `:1359`, `:2152`, `:2206`, `:2580`, `:2726`.

### 3. Exchange: the NX desk (quotes, bands, tickers)

1. Boot: `recover` starts the desk when `-Dslums.exchange.desk=true` — R from the stored row, else the book's 7-day VWAP, else `NxGuard.START_PRICE` (`src/main/java/soloMapling/Economy/exchange/Exchange.java:555-573`, `Desk.start` at `src/main/java/soloMapling/Economy/exchange/Desk.java:78-97`). A missing or undecodable `exchange_desk` row is a **halt**, not a default: "the desk cannot quote without its stored R" (`src/main/java/soloMapling/Economy/exchange/Exchange.java:565-575`).
2. One rate `R` = mesos per 1,000 NX. The house buys at `buy() = floor(R·(1−spread))` and sells at `sell() = ceil(R·(1+spread))` (`src/main/java/soloMapling/Economy/exchange/DeskConfig.java:62-70`, spread default 200 bps at `:35`); a player trading at the quote pays/receives exactly that (`Desk.quote`, `src/main/java/soloMapling/Economy/exchange/Desk.java:118-120`, `Desk.mesos` rounding at `:171-174`).
3. `@nx sell 500` or a site `preview` with no price → `deskPreview` (`src/main/java/soloMapling/Economy/exchange/Exchange.java:990-1065`): refuses a typed price ("the NX desk trades at its quote"), `DESK_CLOSED` via `closeReason` (`:185-190`), minimum quantity from `DeskConfig.minQty`, live-character and presence checks, house inventory via `deskInventory` (`:3220`), `DESK_EMPTY` when the house is short (`deskShort`, `:1068-1080`), then a 24-hex one-use token (`holdDesk`, `:1082-1100`).
4. `@nx confirm` → `deskFill` (`:1107-1152`): the token is consumed (`:1109`), the quote is re-tested — a moved `R` returns `QUOTE_MOVED` with a fresh token (`deskQuoteMoved`, `:1155-1168`) — the exact mesos are recomputed at the current quote, and the money moves through `commitFill` (`:1386-1421`): BUY = player mesos → HOUSE mesos, optional fee → FEES, HOUSE NX → player NX (`:1394-1398`); SELL = player NX → HOUSE NX, HOUSE mesos → player mesos net of fee, fee → FEES (`:1400-1403`). A failed commit calls `desk.undoFill` so the hour's volume and the next step never count a fill that did not happen (`:1413-1414`, `src/main/java/soloMapling/Economy/exchange/Desk.java:202-216`).
5. The hourly step: `tickDesk` (`src/main/java/soloMapling/Economy/exchange/Exchange.java:1475-1497`) runs at most once per `Desk.HOUR_MS` (`:1481-1483`), reads the NX float from the store (`:1485-1491`), and calls `Desk.tick` (`src/main/java/soloMapling/Economy/exchange/Desk.java:222-249`): `raw = driftBpsPerPct × (netFlowNx · 100 / floatNx)` (`:230`), clamped to ±`maxStepBps` (`:231`), applied as `mid + mid·step/10_000` with a one-meso rounding guard (`:232-237`), then inside the day cap around the UTC day's first R (`:238-239`) and inside `NxGuard.clamp` (`:240`). The new state is committed with an empty batch (`src/main/java/soloMapling/Economy/exchange/Exchange.java:1492-1497`).
6. Bands. Two independent rails: `NxGuard` (relative 50 %..200 % of the official rate, `-Dslums.exchange.nxBand.*`, `src/main/java/soloMapling/Economy/exchange/NxGuard.java:40-62`) and a hard window no property moves — `NX_LOWEST = 2_500_000` … `NX_HIGHEST = 10_000_000` per 1,000 NX (`:52`, applied at `:87-88`, `:94`). `Exchange.outOfWindow` (`:350-363`) enforces the hard window on every order; `Desk` also clamps every quote (`:240`).
7. Tickers. One `OrderBook` per ticker, all priced in mesos (`src/main/java/soloMapling/Economy/exchange/Exchange.java:397`, `newBooks` `:457`); `Ticker` declares NX plus Maple Leaf/Chaos/White Scroll/Power Elixir and any catalog row (`src/main/java/soloMapling/Economy/exchange/Ticker.java:16-20`, `:44-55`), built by `Ticker.fromSystem` (`:136-166`): NX first, `-Dslums.exchange.tickers` filter, then catalog categories from `exchangeTickers.yaml` via `ExchangeCatalog.templates` (`src/main/java/soloMapling/Economy/exchange/ExchangeCatalog.java:43-73`), then per-ticker overrides (`src/main/java/soloMapling/Economy/exchange/Ticker.java:168-180`). An item ticker escrows the item and pays mesos; NX is the desk's while the desk runs.
8. House supply. With the desk on, the NX book is off (`src/main/java/soloMapling/Economy/exchange/Exchange.java:669-671`, message from `deskBookOffMessage`, `:976`), regulars no longer quote NX (`tickRegulars`, `:2744-2752`), and item-ticker makers quote at fair value only when `-Dslums.exchange.itemMaker=true` (`makerQuotes`, `:2789`, `ExchangeLimits.itemMaker` at `src/main/java/soloMapling/Economy/exchange/ExchangeLimits.java:75-77`). A trader bot trades the same desk with no token and its own caps (`deskBot`, `src/main/java/soloMapling/Economy/exchange/Exchange.java:1263-1360`; `DeskBotCaps`, 2,000 NX/bot/hour and 20,000 NX/world/hour, memory only, `src/main/java/soloMapling/Economy/exchange/DeskBotCaps.java:18-21`).

### 4. Merchant pricing and restock (bot shops, FM bots, resale pool)

1. A selling merchant bot picks its next item in `SellingMerchantBot.selectNextItem` (`src/main/java/soloMapling/ArtificialPlayer/BotTypes/SellingMerchantBot.java:98-135`). With `-Dslums.bots.merchantpoolstock=false` (the shipped state, `src/main/java/soloMapling/ArtificialPlayer/BotSupportSwitches.java:45`) it **mints** a fresh item from a stock generator and prices it (`:124-128`), recording the mint in the ledger (`:170`, `EconomyLedger.minted(ITEM, LEDGER_SOURCE)`); with the switch on it only draws what the bot economy already holds (`stockFromPool`, `:112-113`, `:179-193`) and mints nothing.
2. Pricing is `askingPriceFor` (`:145-154`): `getItemMarketValue` → `ScrollMarketPrice.price(itemId, raw)` for scrolls → the FM adjustment rules on `raw × 0.9`. A `null` price means the pool cannot value the item, and the bot neither stocks nor sells it (b271, `:122-134`).
3. Bot-run shops (the 6-hour hired-merchant shops) are opened from `BotShops.townTick` (`src/main/java/soloMapling/Economy/BotShops.java:131-153`) when the bot is level ≥ `botShops.minLevel` (15) and fewer than `botShops.maxShops` (8) are open; `openOnce` (`:198-291`) fills the shop with `sellable` items (`:297-324`: equips/use/setup/etc, USE only scrolls or skill books, `SaleRules.whyNotListOwn` at `:314`) plus resale-pool items.
4. The ask is `BotShops.askFor` (`:327-339`): `base = RESALE ? max(fair·qty, paid) : fair·qty`, marked up by `botShops.resaleMarkup` 1.15 or `lootMarkup` 1.0, floored at `2 × npcPrice × qty`, then `PriceBand.nice` — so a bot never lists under twice the NPC buy-back.
5. Sales: `BotShops.onSold` (`:514-532`) removes the listing, credits `owed` to the bot, books `EconomyMeters.BOT_SHOP_SALES`, and closes the shop when the last item goes. The money reaches the bot at its next town tick (`collect`, `:155-176`). FM shopper bots never buy a bot-shop listing (`isListed`, `:509-512`).
6. Restock from players: what a bot buys goes into the resale pool (`offerResale`, `:535-546`; cap `botShops.resalePoolMax` 200) and is drawn back out at open time (`drawResale`, `:575-589`). Items a closing shop cannot give back wait in `PendingGrants` (memory only, `src/main/java/soloMapling/Economy/PendingGrants.java:34-72`).
7. Player-facing shop prices and sinks: NPC purchase/sale through `src/main/java/server/Shop.java` (buy `:104-160`, sell `:237-256`, recharge `:270-296`), with the b289 charge parity at `:109-117` — a rechargeable is granted as one whole `slotMax` stack and therefore charged through the *same* WZ expression that selling it pays (`ItemInformationProvider.getPrice`, `src/main/java/server/ItemInformationProvider.java:498-510`). FM/player-shop sales charge `MesoSinks.shopFee` = `min(price, max(Trade.getFee(price), shopTaxPercent%))` (`src/main/java/soloMapling/Economy/MesoSinks.java:40-48`, 3 % default) and feed the price board through `onShopSale` (`:61-114`: TAX meter, `recordFmTax`, `recordFmSale`, `PriceBook.recordBetween` for two real players else `PriceBook.record`).

### 5. The market volatility path

1. `MarketVolatility.startIfEnabled` (`src/main/java/soloMapling/Economy/exchange/volatility/MarketVolatility.java:79-103`) starts one `MIN_PRIORITY` daemon every 30 s when any of traders / events / rumours is on (`:84`); traders and rumours need `-Dslums.exchange=true` (javadoc `:25-32`).
2. `tick` (`:137-158`): skip while the server is quiescing (`:138`), maybe roll a random world event (`:141` → `MarketEvents.maybeRandom`, `src/main/java/soloMapling/Economy/exchange/volatility/MarketEvents.java:351`), bail if the exchange is off (`:142-145`), pay waiting exchange payouts into online bots (`collectBotPayouts`, `:146`, `:161-168`), recompute fair value hourly (`:151` → `FairValue.maybeUpdate`, `src/main/java/soloMapling/Economy/exchange/volatility/FairValue.java:148-155`), give each online trader its turn (`:152-154`), maybe make a rumour (`:155-157`).
3. Flows are the input. `MarketFlows` keeps 24 hourly buckets per ticker: a supply event is a drop/offscreen find or an exchange taker sell, a demand event is an NPC sink, a shop sale, bot consumption or an exchange taker buy (`src/main/java/soloMapling/Economy/exchange/volatility/MarketFlows.java:6-16`, `:47-67`). Producers: mob drops `src/main/java/server/maps/MapleMap.java:695`, `:812`; NPC sale `src/main/java/server/Shop.java:243`; scripted gain/loss `src/main/java/scripting/AbstractPlayerInteraction.java:728-730`; bot grinding `src/main/java/soloMapling/ArtificialPlayer/BotTypes/TrainingBot.java:2845`; exchange fills `src/main/java/soloMapling/Economy/exchange/Exchange.java:1849-1856`; offscreen finds `src/main/java/soloMapling/Economy/exchange/volatility/MarketVolatility.java:193-228`, `:244-300`.
4. Fair value per ticker (`src/main/java/soloMapling/Economy/exchange/volatility/FairValue.java:10-26`, `:107-128`): `floor` = NPC shop buy price (LEAF pinned by `-Dslums.exchange.LEAF.anchor`, default 500,000, `:193`), `ceiling` = max(1.2 × floor, the sink utility from `ROOTY_TIERS`), `raw = clamp(floor·(1 + k·(demand−supply)/max(supply,1)), floor, ceiling)` with `k` 0.5, then an EMA with α 0.3 (`:92-101`). It is published as `fair` per ticker in `exchange-tickers.json` (`src/main/java/soloMapling/Economy/exchange/ExchangeSite.java:463`).
5. Trader turns (`MarketTraders.tick`, `:222-257`; `act`, `:269-...`): each roster bot waits a jittered 4–12 min, collects what the exchange owes it, picks a ticker (LEAF 70 % bias), reads the book, fills, events, news and rumours, then acts through `Exchange.placeBot` (`src/main/java/soloMapling/Economy/exchange/Exchange.java:2514`) or the desk (`deskBot`, `:1263`; desk turn 35 % of turns, `src/main/java/soloMapling/Economy/exchange/volatility/MarketTraders.java:297`, `:374-478`, `:630`). Every player limit applies to a bot; a bot that cannot pay does not post, so nothing is minted (javadoc `src/main/java/soloMapling/Economy/exchange/Exchange.java:2499-2516`).
6. Brains: `TraderBrain` holds the 3× band around the anchor (`src/main/java/soloMapling/Economy/exchange/volatility/TraderBrain.java:116-124`), `decide` (`:127`) and the news-driven rules (`newsActions`, `:265`). `MarketEvents.pressure` (`:385`, `:394`) and `MarketRumours.pressure` (`:215`) tilt the decision; a rumour can be fake (`MarketConfig` `fakePct` 35) but only ever moves a bot inside its band.
7. Announcement: `ExchangeSite.announcedEvents` (`src/main/java/soloMapling/Economy/exchange/ExchangeSite.java:498-507`) publishes only announced events (never a secret one) into `exchange-tickers.json`.

## Invariants

- **Every movement of NX or mesos inside the exchange is a `Ledger.Posting`**, one append-only `exchange_ledger` row; balances are sums over that table and `reconcile` compares them at boot (`src/main/java/soloMapling/Economy/exchange/Ledger.java:79-125`, `src/main/java/soloMapling/Economy/exchange/Exchange.java:478-480`, `:607`). A mismatch halts, never auto-fixes (`src/main/java/soloMapling/Economy/exchange/Exchange.java:578`).
- **A posting is validated before it exists**: amount > 0, both legs the same asset, no self-posting, a WALLET leg needs an account (`src/main/java/soloMapling/Economy/exchange/Ledger.java:87-106`).
- **Escrow in the same transaction as the book change.** The in-memory book only advances after the store accepted the batch; on failure the book and rows are restored from the copies taken at `src/main/java/soloMapling/Economy/exchange/Exchange.java:1783-1784` (`:1826-1830`).
- **One write is one DB transaction, with wallet rows locked in id order** (`src/main/java/soloMapling/Economy/exchange/JdbcExchangeStore.java:74-105`, `:116-131`); items move only through a character's own bags, either the live one under its save lock or its offline bag (`:155-175`).
- **No bot mints value.** A bot places only what it holds (`src/main/java/soloMapling/Economy/exchange/Exchange.java:2499-2516`), regulars are funded only from a live house wallet (`fundHouseLive`, `:2248`), and a desk fill needs both house buckets (`deskShort`, `:1068-1080`).
- **Every NX order, and therefore every fill at a resting price, sits inside the hard window** 2,500..10,000 mesos per 1,000 NX (`src/main/java/soloMapling/Economy/exchange/NxGuard.java:52`, `src/main/java/soloMapling/Economy/exchange/Exchange.java:1770-1775`).
- **The desk never trades at a rate nobody has seen**: no stored R and no readable desk state is a halt, not a default (`src/main/java/soloMapling/Economy/exchange/Exchange.java:565-575`).
- **A preview moves nothing and a token is single-use** (`src/main/java/soloMapling/Economy/exchange/Exchange.java:1109`), and `halt` clears every outstanding token (`:3024-3026`).
- **Bots never pay more than their band**: `TradeSession` prices with `PriceBook` and clamps with `PriceBand` in code, so no language model output can push a bot outside it (`src/main/java/soloMapling/Economy/HaggleBrain.java:14-18`, `src/main/java/soloMapling/Economy/PriceBand.java:38-108`).
- **Nothing throws into the game**: the shop hooks, the board cycle and both daemons catch and log (`src/main/java/soloMapling/Economy/MesoSinks.java:61-114`, `src/main/java/soloMapling/Economy/exchange/volatility/MarketVolatility.java:125-135`, `src/main/java/soloMapling/Economy/exchange/ExchangeService.java:83`).
