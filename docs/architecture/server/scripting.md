# Graal scripting and event instances

## Purpose

Nearly all game content that is not a handler lives in JavaScript under `scripts/`: 2102 `.js` files drive NPC conversations, quests, portals, reactors, map entry hooks, item use and every party quest. Java owns the engine, the per-client script session, the object handed to the script (`cm`, `im`, `qm`, `rm`, `ms`, `em`/`eim`) and the event-instance lifecycle. `scripts/event/*.js` are not one-shot scripts: each one is evaluated once per channel at boot and becomes a factory (`setup`) plus a callback table (`playerEntry`, `changedMap`, `monsterKilled`, `clearPQ`, `dispose`, …) that the server calls back into while an instance runs.

## How it works

1. **Engine creation.** Each manager extends `AbstractScriptManager`, whose constructor is the only place a `ScriptEngineFactory` comes from: `new ScriptEngineManager().getEngineByName("graal.js").getFactory()` (src/main/java/scripting/AbstractScriptManager.java:44-46). `getInvocableScriptEngine(path)` resolves `Path.of("scripts", path)` (AbstractScriptManager.java:49), returns `null` when the file is missing (AbstractScriptManager.java:50-52) — the "not coded" path everywhere — obtains a fresh engine from the factory (AbstractScriptManager.java:54), rejects anything that is not a `GraalJSScriptEngine` (AbstractScriptManager.java:55-57), enables host access (AbstractScriptManager.java:59), evaluates the file as UTF-8 (AbstractScriptManager.java:61-62) and logs `"Exception during script eval for file: {}"` and returns `null` on `ScriptException | IOException` (AbstractScriptManager.java:63-66). `enableScriptHostAccess` sets `polyglot.js.allowHostAccess`, `allowHostClassLookup` and `allowIO` to true in the engine scope (AbstractScriptManager.java:84-89) — `allowIO` is ours, which is what lets scripts `Java.type(...)` into server classes and read `scripts/json/*`.
2. **Per-client engine cache.** `getInvocableScriptEngine(path, Client)` reads `c.getScriptEngine("scripts/" + path)` but on a miss stores `c.setScriptEngine(path, engine)` — the read key has the `scripts/` prefix, the store key does not (AbstractScriptManager.java:71-79). `resetContext` removes `"scripts/" + path` (AbstractScriptManager.java:91-93). Consequence: the hit path is never taken and the remove never matches, so a script is re-evaluated on every interaction and every engine a client ever loaded stays in `Client.engines` (src/main/java/client/Client.java:108) until disconnect nulls the map (Client.java:1160, :1176).
3. **NPC talk.** `NPCTalkHandler.handlePacket` rejects dead/undead clients (NPCTalkHandler.java:43-46), enforces the NPC-click cooldown against `BLOCK_NPC_RACE_CONDT` (NPCTalkHandler.java:48-51), refuses while a conversation is already open (`c.getCM() != null || c.getQM() != null`, NPCTalkHandler.java:66-69), then special-cases the world-event NPC (`"worldEventNpc"`, NPCTalkHandler.java:72-73), the cosmetic meso sink (NPCTalkHandler.java:74-76), gachapon ids (NPCTalkHandler.java:77-78), `"Maple TV"` (NPCTalkHandler.java:79-80) and the rebirth NPC (NPCTalkHandler.java:81-82) before the generic `NPCScriptManager.getInstance().start(c, npc.getId(), oid, null)` with a shop fallback when the NPC is uncoded (NPCTalkHandler.java:84-95).
4. **NPC script start and callbacks.** `NPCScriptManager.start(Client, int npc, int oid, String fileName, Character, boolean itemScript, String engineName)` disposes any conversation still open for that client (src/main/java/scripting/npc/NPCScriptManager.java:125-127), checks `c.canClickNPC()` (NPCScriptManager.java:128; 500 ms window, src/main/java/client/Client.java:1731-1733), loads `"npc/" + fileName + ".js"` (NPCScriptManager.java:133) or `"item/" + fileName + ".js"` for an item script (NPCScriptManager.java:137), falls back to `"npc/" + npc + ".js"` and `cm.resetItemScript()` (NPCScriptManager.java:140-143), logs `"No script for npc {} (file {}, item script {}): nothing to run"` (NPCScriptManager.java:145), injects the manager object under the engine name (`cm` for NPC, `im` for items, NPCScriptManager.java:149), marks the click (NPCScriptManager.java:153) and invokes `start`, retrying `start(chr)` on `NoSuchMethodException` (NPCScriptManager.java:155-162). Selection events go through `action(c, mode, type, selection)` (NPCScriptManager.java:179-192) which invokes `action` and disposes on error. Every script call from then on re-enters Java through `AbstractPlayerInteraction` (src/main/java/scripting/AbstractPlayerInteraction.java:71): `warp` (:133), `getMap` (:116), `gainItem` (:630), `dropMessage` (:772), `getEventManager` (:236), `getEventInstance` (:240); `NPCConversationManager` adds the dialogue verbs (`sendNext`, `sendYesNo`, `sendGetNumber`, …) and the server ops scripts may call (src/main/java/scripting/npc/NPCConversationManager.java:82, ctors :104/:108/:115).
5. **Dispose of a conversation.** `NPCMoreTalkHandler` also carries the terminating cases: `lastMsg == 2` routes a text-box answer to `QuestScriptManager` or `NPCScriptManager` (NPCMoreTalkHandler.java:41-50), `action == 0` calls `cm.dispose()` / `qm.dispose()` (NPCMoreTalkHandler.java:52-56) and `lastMsg == 3` clamps the number box before dispatch (NPCMoreTalkHandler.java:69-75). `NPCScriptManager.dispose(cm)` clears the CS flag, sets the NPC cooldown, drops the conversation and its invocable, tells `CashShopPartnerRings.dialogClosed` when the script was the partner-ring prompt, resets the engine context and flushes delayed quest updates (NPCScriptManager.java:194-213).
6. **Quest scripts.** `QuestScriptManager.start(Client, short questid, int npc)` builds a `QuestActionManager`, refuses when `!quest.hasScriptRequirement(false)` (src/main/java/scripting/quest/QuestScriptManager.java:70), logs `"START Quest {} is uncoded."` when the file is absent (QuestScriptManager.java:77), injects `qm` (QuestScriptManager.java:82) and invokes `start((byte)1, (byte)0, 0)` (QuestScriptManager.java:87). Hand-in mirrors it through `end`, gated on status `STARTED` and on the map holding the NPC or the quest being auto-complete (QuestScriptManager.java:110-122, invoke at :139). `getQuestScriptEngine` falls back to `quest/medalQuest.js` for medal quests (QuestScriptManager.java:51-58).
7. **Item scripts.** `ScriptedItemHandler.handle` validates the slot still holds the item (ScriptedItemHandler.java:62-66), calls `ItemScriptManager.runItemScript` (ScriptedItemHandler.java:67), logs one line per use and always sends `enableActions` in a `finally` because the client locks itself after the `0x4E` request (ScriptedItemHandler.java:73-79). `ItemScriptManager` is not an `AbstractScriptManager`: it hands straight to `NPCScriptManager.start(c, scriptItem, null)` with `itemScript = true` and engine name `im` (src/main/java/scripting/item/ItemScriptManager.java:36-38; src/main/java/scripting/npc/NPCScriptManager.java:88-89), which is why `scripts/item/*` speak the NPC dialogue API.
8. **Portal scripts.** `PortalScriptManager.getPortalScript` caches `PortalScript` interfaces by `"portal/" + name + ".js"` (src/main/java/scripting/portal/PortalScriptManager.java:66-70), loads through `iv.getInterface(PortalScript.class)` (PortalScriptManager.java:77) and throws when the file does not implement the one-method interface (PortalScriptManager.java:79; src/main/java/scripting/portal/PortalScript.java:24-26). `runPortalScript` maps the result onto `Outcome.RAN | REFUSED | NO_SCRIPT | ERROR` (PortalScriptManager.java:108-119) and `GenericPortal.runScript` logs `"portal script <name> by <chr> on <map>: <outcome>"` (src/main/java/server/maps/GenericPortal.java:181-190, :212-214), rate-limited per identical line to once a minute (GenericPortal.java:192, :199-209). `PortalFactory` uses `isScriptAvailable` to invent a `<mapId>.<portalName>` script for WZ portals that have none (src/main/java/server/maps/PortalFactory.java:66-79); that check evaluates the whole file and does not cache (PortalScriptManager.java:46-59).
9. **Reactor scripts.** `ReactorScriptManager` caches nothing but drops, which come from SQL `SELECT itemid, chance, questid FROM reactordrops WHERE reactorid = ? AND chance >= 0` (src/main/java/scripting/reactor/ReactorScriptManager.java:84-103, query :89). `hit`, `act`, `touch`, `untouch` are all optional — a `NoSuchMethodException` from `hit` is swallowed (ReactorScriptManager.java:64-65). `initializeInvocable` loads `"reactor/" + id + ".js"`, builds `new ReactorActionManager(c, reactor, iv)` and injects it as `rm` (ReactorScriptManager.java:131-142).
10. **Map scripts.** `MapScriptManager.runMapScript` suppresses the `firstUser` variant for a character that already ran it (`chr.hasEntered`, src/main/java/scripting/map/MapScriptManager.java:53-57), reuses the cached `Invocable` (MapScriptManager.java:60-68) or loads `"map/" + path + ".js"` and caches it (MapScriptManager.java:71-77), and invokes `start(new MapScriptMethods(c))`. `MapleMap` fires `onFirstUserEnter` when the map's first character is a real player (src/main/java/server/maps/MapleMap.java:2900-2902) or when a real player arrives at a map that only bots occupy (MapleMap.java:2904-2908), and `onUserEnter` for every non-bot entry (MapleMap.java:2909-2913); bots never trigger either.
11. **Event instance lifecycle — create.** An NPC script fetches the channel's manager with `cm.getEventManager("KerningPQ")` (scripts/npc/1012112.js:52; `AbstractPlayerInteraction.getEventManager` → `Client.getEventManager` → `Channel.getEventSM().getEventManager`, src/main/java/client/Client.java:364-366, src/main/java/net/server/channel/Channel.java:362, src/main/java/scripting/event/EventScriptManager.java:69-75, which returns the `0_EXAMPLE` manager for unknown names). The script checks eligibility, then calls `em.startInstance(party, map, difficulty)` (scripts/npc/1012112.js:74), which lands in `EventManager.startInstance(int lobbyId, Party, MapleMap, int difficulty, Character leader)`: `isDisposed` (src/main/java/scripting/event/EventManager.java:686), `KpqLobby.yieldFor` so a real party takes the channel from a bot run (EventManager.java:690), `startSemaphore.tryAcquire(7777, MILLISECONDS)` (EventManager.java:693, permit :81), a lobby from `availableLobbyInstance()` or `startLobbyInstance` (EventManager.java:699-704), then `createInstance("setup", difficulty, …)` = `(EventInstanceManager) iv.invokeFunction("setup", args)` (EventManager.java:712, :387-389) and `registerEventInstance` (EventManager.java:713). The script's `setup` creates the instance with `em.newInstance(...)` (scripts/event/KerningPQ.js:136 → `EventManager.newInstance`, EventManager.java:218-235, which reuses a ready instance or constructs `new EventInstanceManager(this, name)`), sets properties, spawns stages and calls `eim.startEventTimer(eventTime * 60000)` (scripts/event/KerningPQ.js:137-140 → src/main/java/scripting/event/EventInstanceManager.java:367-373). Back in Java: `setLeader` (EventManager.java:726), `registerParty` (EventManager.java:728 → `EventInstanceManager.registerPlayer`, EventInstanceManager.java:316-340, which stores the character, calls `chr.setEventInstance(this)` and invokes `playerEntry` at :335), then `startEvent()` → `invokeScriptFunction("afterSetup", …)` (EventManager.java:731; EventInstanceManager.java:1412-1420), and finally the automation seam `MechanicsRuns.onInstanceStarted(eim, false)` (EventManager.java:733).
12. **Event instance lifecycle — stages.** While the instance runs, the server calls script callbacks by name: `changedMap`/`afterChangedMap` on warp (EventInstanceManager.java:543, :550), `monsterKilled` (:585), `allMonstersDead` (:592), `playerDead`/`playerRevive` (:646, :732), `playerDisconnected` (:744), `leftParty`/`disbandParty` (:972, :980), `clearPQ` (:991), `playerExit` (:1016), plus anything a script schedules with `eim.schedule(...)` (:854; e.g. scripts/event/KerningPQ.js:151). Portal scripts read instance state through `pi.getPlayer().getEventInstance().getProperty(...)` (scripts/portal/kpq1.js:27-37). Clearing goes through `setEventCleared(ExpeditionType)`, which awards achievements, the bot-hook, per-character rewards and quest points and dismisses the clock (EventInstanceManager.java:1424-1460, `awardQuestPoint` at :1450, `dismissEventTimer` at :1458).
13. **Event instance lifecycle — dispose.** `eim.dispose()` nulls each character's instance and delegates (EventInstanceManager.java:778-789). `synchronized dispose(boolean)` guards on `disposed`, invokes the script's `dispose` callback, sets `disposed`, disposes the scheduler, clears characters/mobs and the scheduler reference, cancels `event_schedule`, clears counters and properties, disposes the expedition, and — unless the event was cleared — calls `em.disposeInstance(name)` (EventInstanceManager.java:791-836). `EventManager.disposeInstance` registers `releaseInstance` after `EVENT_LOBBY_DELAY` seconds (EventManager.java:250-256, config read at :255), `releaseInstance` bails if another instance already took the name (EventManager.java:263-274), and the manager's per-instance map is torn down one minute later by `TimerManager` (EventInstanceManager.java:838-847).
14. **Scheduling inside an instance.** `EventScriptScheduler` is a self-cancelling timer wheel: `registerEntry` starts a `TimerManager` task at `MOB_STATUS_MONITOR_PROC` ms only when needed (src/main/java/scripting/event/scheduler/EventScriptScheduler.java:97-116, :108), the task runs due entries (EventScriptScheduler.java:76-83) and cancels itself after `MOB_STATUS_MONITOR_LIFE` idle ticks (EventScriptScheduler.java:55-63). `EventScheduledFuture.cancel` never interrupts (src/main/java/scripting/event/EventScheduledFuture.java:36-38).
15. **Scripted event scripts are loaded per channel at boot.** `Channel` builds `new EventScriptManager(this, getEvents())` and calls `init()` only when the server is online, otherwise only `0_EXAMPLE` is loaded (src/main/java/net/server/channel/Channel.java:147-153); `getEvents()` lists `scripts/event` and strips the last three characters of every entry (Channel.java:506-518), so every entry must be a `.js` file. `initializeEventEntry` evaluates `"event/" + script + ".js"`, wraps it in `SynchronizedInvocable.of(...)`, constructs the `EventManager` and injects it as `em` (EventScriptManager.java:106-112). `Server` re-runs `reloadEventScriptManager` on every channel after boot (src/main/java/net/server/Server.java:1033-1035).
16. **The unsynchronised part.** Graal forbids concurrent access to an evaluated script, so every shared engine is wrapped: `SynchronizedInvocable` makes `invokeFunction`/`invokeMethod`/`getInterface` `synchronized` (src/main/java/scripting/SynchronizedInvocable.java:13-42). Event managers use it; the NPC, quest, portal, reactor and map managers do not — they rely on one engine per client, except the portal manager, whose engines are cached globally by script path and shared by every client.

## Invariants

- Every script is found by literal path `scripts/<dir>/<name>.js` (src/main/java/scripting/AbstractScriptManager.java:49); `Files.exists` is case-sensitive on Linux, which is why ticket 151 (a script opening `"stylist"` when the file is `STYLIST.js`, docs/tickets/68-mapleroot-vs-cosmic-audit.md:46) broke only on the server.
- A manager never throws for a missing or broken script: `getInvocableScriptEngine` returns `null` and the caller logs and disposes (AbstractScriptManager.java:50-52, :63-66; NPCScriptManager.java:145; QuestScriptManager.java:77).
- One script session per client at a time: starting an NPC script disposes the previous one (NPCScriptManager.java:125-127), and the talk handler refuses a second while `getCM()`/`getQM()` is non-null (NPCTalkHandler.java:66-69).
- A client may not click an NPC within 500 ms of the last accepted click (`Client.canClickNPC`, src/main/java/client/Client.java:1731-1733); quest and NPC managers both re-check it (NPCScriptManager.java:128, QuestScriptManager.java:67).
- An instance stops calling scripts once disposed: `invokeScriptFunction` returns `null` instead of invoking (EventInstanceManager.java:304-310).
- Every `scripts/event` entry must end in `.js`, because `Channel.getEvents` strips three characters unconditionally (Channel.java:506-518); all 125 entries are plain `.js` files today.
- Neither bots nor `onFirstUserEnter` double-fire: both map-script gates check `BotHelpers.isBot(chr)` and the "only real player" condition (MapleMap.java:2900-2908).
- A script engine shared across clients must be wrapped in `SynchronizedInvocable` (src/main/java/scripting/SynchronizedInvocable.java:11-42); only the event managers do this.
- `setEventCleared` must run before disposal for a cleared event, or the lobby is released through `em.disposeInstance` (EventInstanceManager.java:829-836).
